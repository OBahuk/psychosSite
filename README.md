# Дарця — сайт-візитка

One-page site for psychologist and coach Дарця. The page is Ukrainian, static, and built with Vite. Every text, price, contact, and the booking link lives in one file: [`content/site.js`](content/site.js).

Сайт однією сторінкою: хто вона, з чим працює, як проходить терапія, формати й вартість, запис, питання і контакти. Збирати заново нічого не треба — правите один файл і деплоїте.

## Що редагувати

Відкрийте `content/site.js`. Поруч із кожним полем є коментар. Після збереження:

```bash
npm install
npm run dev
```

Сайт відкриється на `http://127.0.0.1:5173`. Перевірка збірки:

```bash
npm test
```

## Що ще треба підтвердити

Цього в профілі не було, тож на сайті стоять явні прогалини, а не вигадані дані.

- **Прізвище.** `person.surname` порожнє. На сайті лише «Дарця».
- **Контакти.** `contacts.email`, `phone`, `telegram`, `instagram` порожні. Блок контактів пояснює, що вони з’являться.
- **Тривалість подальших парних сесій.** У картці пари написано «тривалість уточнюється». Перша спільна — 50 хвилин.
- **Ціни не затверджені.** Індивідуальна 50 хв — 2300 грн, перша парна — 2200 грн, подальша парна — 2600 грн. Біля кожної стоїть «орієнтовно» (`confirmed: false`). Коли Дарця назве остаточні суми, оновіть числа і поставте `confirmed: true`. Якщо приберете текст `pricing.disclaimer`, примітка під картками зникне.
- **Де сесії** (онлайн, місто, очно) — невідомо. Поле `practice.location` порожнє і не показується.
- **Cal.com** ще не підключений: `booking.calLink` = `PLACEHOLDER`.
- **Адреса сайту** `meta.siteUrl` порожня, доки не увімкнете Pages.

## Запис через Cal.com

Поки `booking.calLink` лишається плейсхолдером, у блоці «Запис на сесію» є спокійне повідомлення, що онлайн-запис незабаром з’явиться, і форма запиту. Бекенда на сайті немає.

Форма працює одним із двох способів (теж у `content/site.js`):

1. **`booking.email`** — кнопка відкриває лист у поштовій програмі (`mailto`).
2. **`booking.formEndpoint`** — адреса сервісу, який приймає звичайний `POST` (Formspree, Getform тощо). Якщо заповнені обидва, використовується адреса форми.

Якщо не заповнено нічого, форму видно, але надіслати її не можна: відвідувач побачить, що надсилання ще не підключене.

### Як підключити безкоштовний Cal.com

1. Створіть безкоштовний акаунт на [cal.com](https://cal.com) і увійдіть на [app.cal.com](https://app.cal.com).
2. У налаштуваннях вкажіть свій часовий пояс. За бажанням підключіть календар (Google Calendar чи інший), щоб зайнятий час не бронювався.
3. Створіть два типи подій (Event types):
   - **Індивідуальна сесія** — 50 хвилин.
   - **Парна сесія.** Перша спільна зустріч у практиці — 50 хвилин. Тривалість подальших ще не підтверджена: поставте 50 хвилин або вже затверджену довжину і коротко поясніть це в описі події. Ціну можна продублювати в описі.
4. Відкрийте свій профіль Cal.com. Посилання має вигляд `https://cal.com/your-name`. Окремі події виглядають як `https://cal.com/your-name/individual`.
5. У `content/site.js` вставте це в `booking.calLink`. Домен можна лишити, сайт його прибере.
   - Краще вставити **профіль** `your-name`: у віджеті будуть обидва типи сесій.
   - Якщо потрібна лише одна подія, вставте `your-name/individual`.
6. Збережіть і задеплойте. Форма зникне, на її місці буде офіційний inline-віджет Cal.com (скрипт `https://app.cal.com/embed/embed.js`).

Перевірити віджет до того, як буде власне посилання, можна публічним демо Cal.com: тимчасово поставте `calLink: "rick/get-rick-rolled"`, виконайте `npm run dev`, відкрийте блок запису, потім поверніть `PLACEHOLDER`.

## Локально

Потрібен Node.js 20 або новіший.

```bash
npm install
npm run dev      # розробка
npm test         # збірка і перевірка сторінки
npm run preview  # подивитись уже зібраний dist
```

`BASE_PATH` потрібен лише для GitHub Pages у підкаталозі. Локально його не задавайте: адреса лишається `/`.

## GitHub Pages

У репозиторії є workflow [`.github/workflows/pages.yml`](.github/workflows/pages.yml). Він збирає сайт на кожен pull request і деплоїть лише з гілки `main`.

1. У репозиторії на GitHub відкрийте **Settings → Pages**.
2. У **Build and deployment** поставте **Source: GitHub Actions**.
3. Злийте зміни в `main`. Workflow збере `dist` і опублікує його.
4. Адреса проєктного сайту: `https://<user>.github.io/<repo>/` (для цього репозиторію — `https://obahuk.github.io/psychosSite/`).
5. Вставте цю адресу без слеша в кінці в `meta.siteUrl` і запуште ще раз. Тоді з’являться canonical і картинка для соцмереж.
6. Якщо репозиторій називається `<user>.github.io` (сайт у корені домену), у workflow замініть `BASE_PATH` на `/`. Інакше стилі й фото шукатимуться не в тій папці.
7. Власний домен, якщо з’явиться: **Settings → Pages → Custom domain**, і ту саму адресу в `meta.siteUrl`. `BASE_PATH` для власного домену теж `/`.

## З чого складається

```
content/site.js          єдиний вміст
src/render.js            збірка HTML з цього вмісту
src/booking.js           віджет Cal.com або форма
src/styles.css           стилі
src/main.js              меню, форма, дрібна поведінка
public/images/darcya.jpg фото
public/favicon.svg
.github/workflows/pages.yml
```

Сторінка віддається готовим HTML, тож текст бачать і пошуковики, і браузер без JavaScript. Меню на вузькому екрані без JavaScript просто розкрите. Календар Cal.com підключається їхнім офіційним кодом лише коли `calLink` справжній.
